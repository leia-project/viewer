# AGENTS.md

Leia Open Source 3D Viewer — a generic, config-driven Cesium-based 3D viewer for Digital Twin purposes, built with **SvelteKit + TypeScript + Svelte 4** and the **Carbon Design System** (`carbon-components-svelte`). An initiative by Geodan and Provincie Zeeland.

## Maintaining this file

Keep this document a living source of truth. Whenever a change warrants it — new architectural decisions, conventions, build/setup steps, gotchas, or pitfalls discovered while working — update AGENTS.md in the same change so it stays accurate. Conversely, if a change documented here is later reverted, revert the corresponding AGENTS.md entry as well so the docs never describe code that no longer exists.

## Setup & commands

```sh
npm install
npm run dev              # vite dev server on port 4200
npm run build            # Node (SSR) build → ./build
npm run build --adapter=static   # static build (uses src/routes-static, output in ./build)
npm run check            # svelte-kit sync + svelte-check (type/a11y checks)
npm run lint             # prettier --check + eslint
npm run format           # prettier --write
```

- **Environment:** Copy `.env.example` to `.env`. `APP_URL` **must** be set or `svelte.config.js` and `vite.config.ts` will throw — both read it at config-evaluation time. `APP_URL` is the base path of the deployment (e.g. `https://site.com/some/path/`); `CESIUM_BASE_URL` and the SvelteKit `base` path are derived from it.
- **No test suite.** Validate changes with `npm run check`. `svelte-check` has a baseline of ~148 pre-existing errors and 2 pre-existing CSS warnings — do not treat those as regressions you introduced. Known baseline offenders: `Button.svelte`, `MapToolCesiumMeasure` ('editting'), Stories, `VectorTilesLayer` private `createLayer`, `set source` indexing unknown.
- **Docker:** `docker build -t 3d-viewer .` then `docker run -p 3000:3000 3d-viewer`.

## Architecture

Two-layer design — **keep the boundary intact**:

- **`src/lib/map-core/`** — framework-agnostic abstraction. Abstract `MapCore`, abstract `Layer`, `LayerConfig`, `LayerLibrary`, `LayerConfigGroup`, an event `Dispatcher`, and `library-connectors/` (CKAN, GeoNetwork) that fetch remote layer catalogs into the layer library. Layer types are registered in `src/lib/map-core/layer-type.ts`.
- **`src/lib/map-cesium/`** — the Cesium implementation. `Map extends MapCore` wraps a `Cesium.Viewer`; `CesiumLayer<T> extends Layer`; `CesiumLayerFactory` turns a `LayerConfig` into a concrete layer class.

Data flow: **JSON config → `LayerConfig` → `CesiumLayerFactory` → `CesiumLayer<T>` subclass → `Map.viewer`**.

Concrete Cesium layers in `src/lib/map-cesium/layers/`:

- **Imagery:** `WmsLayer`, `WmtsLayer`, `BasiskaartLayer`, `ArcGISLayer`, `VectorTilesLayer`.
- **Vector / custom:** `GeoJsonLayer`, `WfsLayer`, `OgcFeaturesLayer`, `IconLayer`, `DroppedGLBLayer`.
- **3D / primitive:** `ThreedeeLayer` (3D Tiles), `I3sLayer`, `ModelAnimation`, `FloodLayer`.

## Configuration (config-driven design)

Behavior comes from a JSON config, **not hardcoded**. New layer/tool capabilities should be exposed through config `settings`. An example is `static/example.config.json`.

Config loading (static build) supports two ways:

1. `?url=http://host/some_config.json` — load config from URL.
2. A `config.json` placed at the build root (ignored when `?url` is supplied).

Top-level config shape:

```jsonc
{
	"viewer": {
		/* base viewer settings (below) */
	},
	"groups": [
		/* layer-library grouping tree */
	],
	"layers": [
		/* layer definitions */
	],
	"tools": [
		/* tool enablement + settings */
	]
}
```

### `viewer`

| key                                  | description                                                                                                                                                        | type    |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------- |
| `startPosition`                      | Start camera position (below)                                                                                                                                      | object  |
| `startCameraMode3D`                  | Start in 3D (true) or 2D (false; pitch forced to -90)                                                                                                              | boolean |
| `startToolOpen`                      | Tool id to open on start (e.g. `layermanager`, `stories`)                                                                                                          | string  |
| `colors`                             | Carbon Design color tokens plus header colors `header-color` (bar background), `title-color` / `sub-title-color` (any CSS color); see `static/example.config.json` | object  |
| `title` / `subTitle`                 | Header title / subtitle                                                                                                                                            | string  |
| `logo`                               | Header logo image URL                                                                                                                                              | string  |
| `logoMarginLeft` / `logoMarginRight` | Header logo margins                                                                                                                                                | string  |

`startPosition` / `cameraPosition` fields: `x` (lon), `y` (lat), `z` (height m), `heading`, `pitch` (-90 down, 0 forward, 90 up), `duration` (fly seconds).

### `groups`

Hierarchical grouping for the layer library; root parent first. Fields: `id` (unique), `title`, `parentId` (empty for root).

### `layers`

Common layer fields: `id`, `type`, `title`, `groupId`, `description`, `imageUrl`, `legendEnabled`, `legendUrl`, `isBackground` (only one active at a time), `defaultAddToManager`, `defaultOn`, `attribution`, `metadata` (array of `{key,value}`), `transparent`, `disablePopup`, `opacity` (0 opaque … 100 transparent), `cameraPosition`, `settings`.

Supported `type` values: `basiskaart`, `wms`, `wmts`, `tms`, `vectortiles`, `3dtiles`, `geojson`, `modelanimation`, `custom` (plus the other classes listed under Architecture). `settings` differs per type — examples:

- **wms:** `url`, `featureName`, `contenttype` (default `image/png`); optional `tools.styleSwitcher.enabled` to pull styles + dynamic legend from GetCapabilities.
- **wmts:** `url`, `featureName`, `contentType`, `matrixids[]`, `tileMatrixSetID` (default `EPSG:3857`), `tileWidth`/`tileHeigth` (256), `maximumLevel`.
- **3dtiles:** `url` (tileset.json), `shadows`, `tilesetHeight`, `enableHeightControl`, `defaultTheme`, `style` (Cesium3DTileStyle; `pointSize` for point clouds), `themes[]`, `filter`.

Refer to `static/example.config.json` for concrete, copy-pasteable examples of every type.

## Key conventions

- **Dual build.** `src/routes/` (Node/SSR, includes `+layout.server.ts` and `hooks.server.ts`) vs `src/routes-static/` (static, no server scripts). `svelte.config.js` swaps the routes folder via `npm_config_adapter` and selects `adapter-node` vs `adapter-static`. A change in one routes folder usually needs mirroring in the other.
- **Cesium import:** `import * as Cesium from "cesium"`. Assets are copied to `/Cesium` via `viteStaticCopy`; `CESIUM_BASE_URL` is derived from `APP_URL`. The viewer is `Map.viewer`; layers attach via `viewer.imageryLayers`, `viewer.dataSources`, `viewer.scene.primitives`.
- **Tools** (`src/lib/components/tools/`): each tool self-registers via `getContext("mapTools").registerTool(new MapToolMenuOption(...))`; `Page.svelte` holds a `toolOrder` map from tool id → Svelte component. Tools are enabled/configured through the config `tools` array.
- **Dependency attributions:** whenever a new package is introduced/installed (for example in `package.json`), add a matching `new Attribution(...)` entry in `src/lib/components/tools/MapToolInfo/MapToolInfoView.svelte` so the in-app attribution list stays complete.
- **PDF exports (Stories + Zonal):** shared page branding/layout primitives live in `src/lib/components/tools/pdf/pdf-layout.ts` (A4 portrait frame, logo header, footer, page metrics, text/pagination helpers). Keep feature-specific content rendering in each tool, but do not duplicate branding constants or header/footer drawing logic. In zonalStatistics, page 1 is a cover (title/timestamp + map screenshot), the screenshot height is capped so cover text/footer stay visible, the selected visible layer title is shown under the screenshot, and the table starts on page 2 with continuous overflow pagination; the title/timestamp are printed on the cover only, not on later table pages. Inside the table pages, each postcode group starts with a full-width shaded zone header row (`Gebied: <postcode>` in Dutch) so the exported rows remain visually separated without forcing one postcode per page; the PDF table itself no longer repeats a separate zone/gebied column, and if a page break happens mid-group the shaded postcode header is repeated on the next page before the remaining rows.
- **`zonalStatistics` is a generic tool.** It ships **no** built-in colours, branding, or klimaatlabels specifics — the "Labelpaspoort" look is entirely config-driven (see `static/example.config.json`). **Map display and table membership are decoupled**: the panel's radio buttons pick which layer's values are painted onto the shared zone geometry (`selectedLayerId` + `selectLayer()`, which only **recolours** the fill primitive — it deliberately does **not** toggle any data layer's `visible` store), while the `+`/trash-can button in each card's foldout adds/removes that layer's **row** in the table (`tableLayers` store + `addTableLayer`/`removeTableLayer`/`isTableLayer`/`clearTableLayers`/`getTableLayers`). `buildTable()` and `buildZoneSlice()` both read `tableLayers`, so the table/exports follow the explicit add/remove, **not** layer visibility. There is no `visibleDataLayers` store and no per-layer `visible` subscription — do not reintroduce them. `resolvedDataLayers` (all layers) still drives the panel cards. `buildZoneSlice(code)` returns entries carrying their `layerId` so the view matches rows by id, never by index. Settings: `zoneLayerId` (required, clickable zone geometry layer); `layers` (required, data layers via `{ id, title?, columns? }` — selectable on the map + addable as rows, `title` defaults to the layer config title, `columns` is a per-layer source-attribute override map keyed by column `key`, value `{ attribute?, tooltipAttribute? }` or a bare string shorthand for `attribute` — this is how datasets that name the same logical column differently (`ambitie_label` vs `label_ca`) feed one table column; every read of a column's value/tooltip/class attribute goes through `attributeFor(layerId, column)` / `tooltipAttributeFor(layerId, column)` / `classAttributeFor(layerId)` in the controller, and `attributesFor(layerId)` replaced the old global `neededAttributes` — do not reintroduce a single shared attribute list); `columns` (required, array of `{ key?, attribute, label?, tooltipAttribute?, styled? }` — `key` is the stable id the per-layer overrides refer to and defaults to `attribute`, `label` defaults to `attribute`, `tooltipAttribute` adds a hover/description + a description column in the PDF and CSV exports (and is rendered inline in PNG/JPEG image exports), `styled:true` colours the cell via `valueStyles`); `zoneCodeAttribute` (defaults to `postcode`; the zone code is the **join key** between separate datasets, so it is normalized via `normalizeCode()` — whitespace stripped, upper-cased — on **both** sides of every index, and `classMapping` values are matched via `normalizeClassValue()`; do not compare raw `String(code)`/`String(value)` again, a casing/space difference between two GeoJSON files then silently yields an empty colour index); `valueStyles` (array of `{ value, color, label? }` mapping categorical cell values to colours — drives styled cell backgrounds, the legend, and PDF cell fills; the text colour is derived automatically from the background via WCAG contrast (black or white), so it is not configurable; PDF fills require **hex** colours, other CSS colours render plain in the PDF); export branding `exportTitle`, `exportFileName`, `pdfFooterText`, `pdfLogo` (title/filename default to the tool title/alias; footer + left logo default to `DEFAULT_PDF_BRANDING` in `pdf/pdf-layout.ts`). The panel/table headers and export title use the tool title (the resolved `label`/`alias`, passed as a `title` prop), not a hardcoded i18n string. Domain model in `zonal-statistics-controller.ts` is `ZoneTable`/`ZoneTableRow` (per-column value+tooltip arrays aligned to `settings.columns`) — no `Passport`/`target` concepts remain. The tool computes **no** statistics summary: the former `buildSummary()`/`ZonalSummary` model, the Turf-based zone-area maths (`zoneAreaSqMeters`/`entityAreaSqMeters`/`toClosedLonLatRing`/`areaCache`) and the `showSummary` setting were removed — do not reintroduce them. The styled-cell/legend/chip colours live in a shared `zonal-style.ts` (`createZonalStyler` → `swatchStyle`/`styleFor`/`cellStyle`/`pdfColor`) used by both the view and the panel — do not duplicate the WCAG-contrast colour maths.
- **`zonalStatistics` numeric formatting:** each `settings.columns[]` item can define `decimals` (integer `0..20`) to round numeric values for that column in the table and all exports; omit `decimals` to keep raw values.
- **`zonalStatistics` column visibility per surface:** `settings.columns[]` can define `hideInTable` (default `false`) to hide/show a column in the interactive table; `hideInImageExport` controls PNG/JPEG image exports. PDF and CSV exports still include all configured columns.
- **`zonalStatistics` performance:** selection is **click** (`mouseLeftClick`) and hover is **`mouseMove`**. Key perf-critical implementation details in `zonal-statistics-controller.ts`: the zone + data-layer polygon **fills are batched Cesium primitives**, **not** GeoJson entities — (a) **exactly one** batched `Cesium.Primitive` of flat `PolygonGeometry` instances is built for the whole tool (`buildZoneFill`, `PerInstanceColorAppearance`, `height:0` / `perPositionHeight:false` — **no terrain is assumed**) in `scene.primitives`, built from the **zone layer's** geometry only. The data layers are attribute joins on the zone code and therefore share that geometry, so switching the panel's radio selection only **repaints the per-instance colours** (`syncFillSource` → `refreshBaseColors`, colours read from the selected layer's `colorIndex` entry (code → RGB), alpha from that layer's `opacity` store via `colorLayerAlpha()`; zones the colour layer has no feature for stay `Color.TRANSPARENT`). Do **not** go back to one primitive per layer (`buildFillRenders`/`buildFillRender`): triangulation time, retained `PolygonGeometry` instances and GPU vertex memory then scale with the number of configured layers, which is exactly what made the tool lag with many layers. Because geometry creation is asynchronous, colour changes issued before `primitive.ready` are re-applied by `schedulePaint()` (a one-shot `scene.postRender` listener that keeps calling `map.refresh()` — the scene runs in `requestRenderMode` — but **only while `primitive.show` is true**, since a hidden primitive never becomes ready). Colours come from the per-layer `colorIndex` (zone code → opaque RGB): for the **zone layer** it is snapshotted from its entity materials (`indexZoneColors` → `readEntityColor`, re-run on its `style`/`legend` change via `restyleZoneColors`), for **data layers** it is computed while parsing their raw GeoJSON. Because a data layer never becomes Cesium entities, the only colour source it has is the **zone layer's `classMapping`** (keyed on its `settings.style` attribute, snapshotted by `buildClassColors()` — this is what makes all datasets share one colour scheme); when no `classMapping` is configured, `featureColor()` falls back to the zone layer's colour for that zone so the geometry still renders. The zone layer's GeoJson entity fills are **hidden** (`entity.polygon.show` set to a **shared** static `ConstantProperty(false)` via `hideEntityFills`, restored on `destroy` via `restoreEntityFills`) so only the primitive renders. The zone boundaries are outlined by **one batched `Cesium.Primitive` of `PolygonOutlineGeometry`** (`buildZoneOutlines`, only the zone layer since data layers share the geometry, flat at `height:0`, `PerInstanceColorAppearance` `flat:true`, depth-test off, added **after** the fills so the lines sit on top, and **`show` bound to the controller's `active` store — not to the zone layer's `visible` store**, because the outlines must stay visible for as long as the tool is open; the outline appearance is **`translucent:true`** — it must render in the same translucent pass as the fills, otherwise (as opaque) it draws in the earlier opaque pass and the semi-transparent fills paint over it; being added last to the primitive collection, Cesium's stable equal-depth sort keeps it on top); the outline is a **static** `OUTLINE_COLOR` black and does **not** recolour with hover/selection (only the fills do), but its **alpha tracks the zone layer's opacity slider** (`outlineColor()`/`applyOutlineOpacity()` subscribe to `zoneLayer.opacity`, updating each outline instance's per-instance colour — instances carry unique ids and `releaseGeometryInstances:false`). The **selected** zones get a thicker (`HIGHLIGHT_WIDTH` 2px) `SELECTED_OUTLINE_COLOR` yellow outline and the **active** zone (the one focused in the table) an `ACTIVE_OUTLINE_COLOR` blue one, drawn by a second batched primitive of `PolylineGeometry` instances (`rebuildHighlightOutlines()` + `zoneRings()`, rebuilt on `toggleZone`/`setActiveZone`/`clearSelection`, added last so it sits on top, `translucent:true` for the same pass-ordering reason). That rebuild is **synchronous** (`asynchronous:false`, the new primitive is added before the old one is removed) and **coalesced into one microtask** (`scheduleHighlightRebuild()`) — a single click changes both the selection and the active zone (the table reacts to the selection), and rebuilding twice asynchronously made the yellow outlines blink and briefly drew the active zone yellow. Polylines because a `PolygonOutlineGeometry` renders as a GL line whose width browsers clamp to 1px; the rebuild is cheap because it only covers the handful of **selected** zones — do **not** extend it to all zones (that is the removed per-zone ground-polyline approach). **Hover has no outline**, only the brightened fill. This is **not** the removed per-zone `GroundPolylinePrimitive`/`cleanRing`/`ringCache` ground-polyline / `rebuildHighlights` approach, and **not** per-zone entities; do **not** revert to either. (b) hover + selection + active state are shown **purely by recolouring the per-instance fill colour** — `stateColor` tints the base label colour (active blends toward `ACTIVE_TINT`, selected + hover **brighten** the base — selected less than hover), preserving the base opacity so the label hue stays visible in every state, applied **incrementally per changed zone code** via `Primitive.getGeometryInstanceAttributes(id).color` (`applyColor`/`paintCode`, guarded by `primitive.ready`), **never** a full rebuild. Each polygon part carries a unique `{ code }` pick-id object, so all parts of a zone recolour together and picking resolves straight to a code. Hover (`onMouseMove`) picks on every `mouseMove` — this is only viable **because** picking now hits one batched fill primitive instead of thousands of entities (the old entity-based hover was removed for being far too slow; the batched primitive is precisely what makes hover cheap). Layer visible/opacity/style changes are mirrored onto the shared fill primitive (`buildZoneFill` store subscriptions: the **zone layer's** `visible` → `syncFillSource` (sets `primitive.show` — the zone layer is the geometry, so it alone drives visibility) and its `style`/`legend` → `restyleZoneColors` (re-snapshot its entity colours, the `legend` subscription being what catches the GeoJSON colour-randomizer whose `style` value is unchanged); every tracked layer's `opacity` → `refreshColorSource`, which repaints **only when that layer is the current colour source**); (c) clicks + hover resolve the zone code from the picked primitive instance id (`pickZoneCode` → `picked.id.code`), validated against `zoneEntityIndex`; (d) the view builds the table **incrementally** (`buildZoneSlice` + `updateTable` in `ZonalStatisticsView.svelte`) — one zone column added/removed per selection change instead of a full `buildTable()` rebuild (`buildTable`/`buildExportRows` remain for exports). (e) **MultiPolygon zones** — Cesium's `GeoJsonDataSource` explodes a MultiPolygon feature into **one entity per part**, all sharing the same code, so `zoneEntityIndex` maps code → **array** of entities and each part becomes its **own fill instance** carrying the same `{ code }` id; `buildZoneFill` emits one `PolygonGeometry` instance per part (keyed in `idsByCode` code → id[]) so `applyColor` recolours every part of a multipart zone together (do **not** collapse to a single instance/id per code — only one part would recolour).
- **`zonalStatistics` view UX (`ZonalStatisticsView.svelte`):** the floating table has CSS scroll-shadow edges (`.edge-*`, toggled by an `on:scroll` handler that also runs on resize and after each table rebuild), row hover, and a live `zonesSelected` count badge in the header. Rows come from `controller.tableLayers` (subscription rebuilds the rows and refills the already-selected zone columns via `fillZoneColumn`, and diffs the layer ids against `knownLayerIds` so **newly added rows flash blue** for `FLASH_MS` via the `flash` class + `zonal-row-flash` keyframes — the tint is an **inset `box-shadow`**, not `background-color`, because styled cells carry an inline background that a class can't override; timers are cleared on destroy and the animation is disabled under `prefers-reduced-motion`); when the table holds no layers the body shows the `tools.zonalStatistics.noTableLayers` hint (this takes precedence over the empty-selection hint) and the export menu is disabled. Each selected zone's column header carries three buttons: activate (`.zone-code`, focuses/tints the zone), zoom (`.zone-zoom`, `ZoomIn` icon → `controller.zoomToZone(code)` flies the camera to the `BoundingSphere` of the zone's polygon parts), and remove (`.zone-remove`). Exports show a `busy-overlay` with a Carbon `InlineLoading` (label from `tools.zonalStatistics.exporting`) and surface failures via a header `InlineLoading` `status="error"` (`tools.zonalStatistics.exportFailed`, auto-clears after 5s). The table exports as PNG, JPEG, PDF or CSV (overflow menu); the `tooltipAttribute` description text is included in every export — a description column in the PDF (`pdfColumns`) and CSV (`csvColumns`), and rendered inline via `.cell-tooltip-text` in the PNG/JPEG snapshot (native `title` tooltips can't render into an image). **PDF column widths are measured, never hardcoded:** `pdfColumns(doc, rows)` → `buildPdfColumns()` measures every header and every cell value with `doc.getTextWidth()` (the font/size must be set on the doc **before** measuring, otherwise the measurements don't match what is drawn) and takes the widest as that column's preferred width; `fitPdfColumnWidths()` then shrinks the surplus above a per-column floor (`minimumPdfColumnWidth()`, the width of `"0000000"` plus padding) proportionally so the table fits `metrics.contentWidth`. `drawPdfTableHeader()` wraps header text with `doc.splitTextToSize()` and grows the header row to the tallest wrapped header instead of a fixed 8&nbsp;mm row — do not reintroduce fixed mm column widths or a fixed header height, long labels get clipped. The PNG/JPEG export does **not** capture the on-screen (wide, zones-side-by-side) table; instead it renders + captures a dedicated off-screen `.export-sheet` (fixed A4-portrait width, `left:-100000px`, bound to `exportElement`) that stacks **one table per selected zone vertically** (layer rows × configured columns) so the image fits on A4 pages. `exportImage` sets `exportingImage`, `await tick()`s for that sheet to render, then captures `exportElement`. CSV export (`exportCsv`) is synchronous, RFC-4180 quoted, and prefixed with a UTF-8 BOM for Excel. The active zone's map fill uses the strongest tint (blended toward `ACTIVE_TINT`, deep sky blue), the other selected zones a milder `SELECTED_TINT` (yellow) blend, and the hovered zone a brightened base — all via `stateColor` in `zonal-statistics-controller.ts` (no separate outline/highlight primitives). Added transitions honour `prefers-reduced-motion`.
- **`zonalStatistics` panel is deliberately flat.** The panel lists one card per resolved data layer in config order; it does **not** nest them in the layer library's group tree. That was tried (a `groupedDataLayers` store + a recursive `ZonalLayerGroup.svelte` mirroring `LayerManagerGroup.svelte`) and rejected as too noisy/unclear for the small panel — do not reintroduce it.
- **`zonalStatistics` panel behavior:** the left-menu panel (`ZonalStatisticsPanel.svelte`) renders **one `ZonalLayerCard.svelte` per resolved data layer**, deliberately minimal. Each card is a **row**: a bordered `.card-box` (head + foldout) and, **outside** that box on the right, the table `+`/trash-can toggle (`tools.zonalStatistics.addToTable`/`removeFromTable`, `Add`/`TrashCan` icons; blue `--cds-link-primary` to add, and to remove it is neutral `--cds-icon-primary` at rest turning `--cds-support-01` red on hover/focus via `.table-btn.danger` (a column of permanently red trash icons reads as an error state — do not make it always-red again); `height:1.5rem` plus `margin:.5rem 0` so its 2.5rem box centres against the head row). Keep it **outside** the grey head and **out of the foldout** — table membership must be visible without expanding every card, and it is not a property of the layer box. The head itself is a single Carbon `RadioButton` whose `labelText` **is the layer title** (one control, one tab stop — do not add a separate title button next to it; the title ellipsises via `:global(.bx--radio-button__label > span:last-child)` and the full name is a native `title` on the wrapper, which `RadioButton` spreads through `$$restProps`), plus, only when `layer.config.opacitySupported`, a chevron (`tools.menu.expand`/`collapse`) folding open the opacity slider. Carbon's wrapper-scoped rule `.bx--radio-button-wrapper .bx--radio-button__label` sets `align-items:flex-start; justify-content:center`, which with the full-width label needed for the ellipsis pads **both sides** of the title and top-aligns the circle against it — the card **must** override it back to `justify-content:flex-start; align-items:center` (plus `width`/`min-width`/`margin-right:0`), or the titles indent unevenly and the circle sits high. `.card-head` carries a `min-height:2.5rem` so heads are equally tall whether or not a card renders the chevron (that is what keeps the radio circles on an even column and centres the outside `+`/trash-can button), and the label text is restyled to Carbon's `label-01` (0.75rem) to match the layer manager's layer titles. The **selected** card is accented (`.is-selected`: `--cds-interactive-01` border + `--cds-selected-ui` head — no inset left bar, the border and head tint carry the selection); the unselected ones are **not dimmed**, because an unselected layer can still have a table row. The radio buttons share a `name="zonal-layer"` and are driven by `checked={$selectedLayerId === layerId}` + a forwarded `on:change` — Carbon's `RadioButton` has **no `group` prop** and `RadioButtonGroup`'s context does not cross slot boundaries, so do not try to wrap the cards in one. It is reimplemented locally rather than recycling `MapToolLayerManager/MapToolLayerControl.svelte` (the data layers are always GeoJSON). The card intentionally has **no** legend, description, metadata link, GeoJSON style options or statistics — do not add them back. There is **no** visibility toggle-all toolbar (the radio makes an "all on/off" state meaningless); `allLayersOn`/`allLayersOff` were removed. There **is** a `.table-header` row above the cards: a `label-01` `tools.zonalStatistics.tableSection` title, a live `N / M` count of layers in the table, and two right-aligned **icon-only** `.icon-btn`s (`Add`/`TrashCan`, labelled `addAllToTable`/`removeAllFromTable`) that add every resolved layer's row to the table (`controller.addAllTableLayers()`, disabled when they are all in) or empty it (`controller.clearTableLayers()`, disabled when it is already empty) — that is table membership, not visibility. They are **transparent at rest with a coloured icon** (`.primary` blue `--cds-interactive-01`, `.danger` red `--cds-support-01`) that **fills with that colour on hover** (white icon), precisely so the bulk actions do not read as another pair of the per-card `+`/trash buttons — do not give them a permanent filled background. They are deliberately **not** Carbon ghost `Button`s with text labels: those wrapped onto two lines in a narrow panel and needed padding overrides to fake alignment. The actions carry no trailing padding, so right-aligning puts the trash button in the same column as each card's `+`/trash button; the panel duplicates the card's small `.icon-btn` rules because Svelte scoped styles cannot be shared and `tosti.scss` is reserved for genuinely global rules. Empty-state text is localized via `tools.zonalStatistics.noDataLayers`. While layers are still resolving the panel renders one `.card-skeleton` per unresolved layer; it **mirrors the card's box/head geometry** (bordered `.card-box`, `min-height:2.5rem` `.card-head`, round 1.125rem radio placeholder, and the button placeholder in a 1.5×2.5rem slot outside the box) so the grey placeholder matches the real card — keep the two in sync when the card layout changes.
- **`zonalStatistics` activation (`MapToolZonalStatistics.svelte`):** opening the tool snapshots **only the zone layer's** visibility (`zoneLayerWasVisible`) and switches it on — it carries the geometry every layer is painted onto — then calls `controller.selectLayer(first)` + `controller.addTableLayer(first)` for the **first entry of `settings.layers`**, so the map shows one layer's values and the table starts with its row. The data layers' `visible` stores are never touched (switching a GeoJson layer on would make Cesium parse its redundant geometry). Closing the tool calls `restoreConfiguredLayers()` (resetting the zone layer to its pre-open visibility and clearing `selectedLayerId`), `controller.clearSelection()` and `controller.clearTableLayers()`.
- **`zonalStatistics` data layers are never materialised in Cesium.** `initialize()` (which runs on `configLoaded`, before the tool is ever opened) loads and indexes **only the `zoneLayerId` layer** — it needs its geometry for the shared fill primitive. The `settings.layers` data layers are merely **resolved** (`map.getLayerById`, no fetch) so the panel can render its cards. On **first use** — `selectLayer()` (via `applySelection`) and `addTableLayer()`/`addAllTableLayers()` — `ensureLayerReady(layerId)` `fetch`es the layer's `settings.url` and `indexLayerProperties()` reads only `neededAttributes` into `valueIndex` and a colour into `colorIndex`; the parsed document is then dropped. Do **not** go back to `layer.ensureLoaded()` / entity-based indexing (`indexLayer`, `colorEntityIndex`) for data layers: every layer then kept a full `GeoJsonDataSource` of `Entity` + `PolygonHierarchy` objects alive, and the tab ran out of memory after switching through ~8 layers even though the geometry is an exact duplicate of the zone layer's. Do **not** `await` every configured layer in `initialize()` either — with ~10 zone datasets that downloads and parses them all on viewer start. The loads are deduped per layer (`layerLoads`) **and serialised through `loadQueue`**, so "add all to table" cannot parse a dozen GeoJSONs in parallel. `applySelection` bails when `selectedLayerId` changed while loading, and `resolveColorLayerId()` only switches to a layer whose `colorIndex` entry is **non-empty** (`.has()` is not enough — an indexed-but-empty map repaints every zone `TRANSPARENT` and leaves bare outlines), so the previously selected layer stays drawn instead of the map blanking out. `loadingLayerIds` drives the per-card spinner in `ZonalLayerCard.svelte`; `dataVersion` is bumped after each layer finishes indexing so `ZonalStatisticsView.svelte` refills the table cells that were still empty.
- **State:** Svelte `writable` stores; the `Map` is a singleton store on `app` (`src/lib/app/app.ts`). Persist a store with `register(store, key)` in `src/lib/app/stores/app-storage.ts` (syncs to `localStorage`).
- **i18n:** `svelte-i18n` with `$_('key.path')`. When adding a key, add it to **all three** files in `src/lib/i18n/json/`: `en.json`, `nl.json`, `fr.json`. `document.documentElement.lang` is kept in sync inside `selectedLanguage.subscribe` in `src/lib/i18n/localization.ts`.
- **Styling:** SCSS + Carbon tokens (`var(--cds-*)`). Global rules (scrollbars, focus-visible outline, `prefers-reduced-motion`) live in `src/lib/styles/tosti.scss` (imported via `CarbonTheme.svelte`); do not add per-component scrollbar overrides.
- **Accessibility:** Prefer a real `<button>` over a clickable div for anything interactive (the `use:clickable` action this file used to reference does not exist in this branch); where a div-button is unavoidable, add `role="button"`, `tabindex`, a key handler and a `<!-- svelte-ignore a11y-click-events-have-key-events -->` comment. The skip link in `Page.svelte` targets `#main-content`.

## Pitfalls (verified, hard-won)

- **Lazy layer loading.** `CesiumLayer` defers data loading until the layer is first visible or a tool explicitly requests it. `protected startLoading()` runs once (latched by `loadInitiated`, never reloads); `public ensureLoaded(): Promise<void>` lets tools load a hidden layer's data without toggling visibility. Most layers (imagery base / threedee / i3s / vectortiles / wfs / ogc) create the SOURCE in `startLoading()`; `addToMap()` is attach-only, triggered by the base `_source.subscribe` — no extra guard needed. A tool that needs a hidden layer's data must `await layer.ensureLoaded()`, not rely on `loaded`.
- **`GeoJsonLayer` is the deliberate exception** to the lazy-source pattern: its source is created eagerly in the constructor and `addToMap` is gated by `if (!this.loadInitiated || !this.source) return;`, with `startLoading()` overridden to call `addToMap()`. Reason: its `addToMap → addListeners()` path reads subclass fields (`this.style`, color defaults, `clampToGround`) that only initialize **after** `super()`, while for `defaultOn:true` layers `startLoading` fires _during_ `super()`. Do **not** centralize the `loadInitiated` check into the base `_source.subscribe` — non-lazy layers (icon/custom/dropped-glb/flood/model) set source in the ctor and rely on the unguarded subscription to attach eagerly.
- **GeoJson `setCustomStyle`.** When `config.settings.style` is an object without a `fill` (e.g. `{stroke:'#0000ff'}`), `Cesium.Color.fromCssColorString(style.fill)` throws (`fill` undefined). Guard it: `const colorProp = settings.style?.fill ? new ColorMaterialProperty(fromCssColorString(...)) : this.defaultColorPolygon;`. Note: reading `entity.properties[attr] * factor` on a Cesium `ConstantProperty` is correct (it coerces via `valueOf`) — do **not** "fix" it with `.getValue()`.
- **GeoJson class style naming.** The strict naming convention is to set `style` to the GeoJSON attribute name (for example `"label"`) and optionally provide `settings.classMapping` for deterministic value-to-color maps on that style attribute.
- **Localized numeric input.** Numeric UI values (e.g. height control) can arrive as locale strings like `4,5` despite numeric typing; normalize before feeding Cesium math, and guard matrix/model transforms against non-finite numbers to avoid render crashes.
- **In-panel tooltips.** Carbon tooltips on right-aligned icon buttons inside a scrolling panel get clipped (the panel's `overflow-y:auto` traps them) and appear "behind the map". z-index does **not** help — set `tooltipPosition="left"` so they open inward. (Separately, the collapsed left-menu icon tooltips that extend right over the map _are_ a stacking issue, fixed by `.tosti-tool-menu { z-index:10 }` in `MapToolMenu.svelte` + `.map-body { position:relative; z-index:1 }` in `Page.svelte`.)
- **Tooltips inside a horizontally-scrollable table (zonalStatistics cells).** Do **not** use Carbon `TooltipDefinition`/popover tooltips inside the `overflow:auto` zonal table: their absolutely-positioned tooltip content is counted in Chrome's scrollable overflow (but not Firefox's), which adds a phantom scrollable empty strip on the right even when the table fits. The cell value tooltips use a plain native `title` attribute (`.cell-tooltip`, dotted underline) instead — no abspos layout, no phantom scroll. Relatedly, the table is `width: max-content` with **no** `min-width:100%` (that `min-width` caused the same phantom strip in Firefox).
- **Scrollbars.** Apply `scrollbar-width: thin; scrollbar-color: var(--cds-text-secondary) transparent;` on a universal `*` selector in `tosti.scss`, not on `html` alone (`scrollbar-width` is not inherited, unlike `scrollbar-color`). Do not add a custom `::-webkit-scrollbar` block alongside the standard props — it makes Chromium ignore `scrollbar-gutter: stable`. To avoid content shift, reserve gutter only in Chromium via `@supports selector(::-webkit-scrollbar) { .content-wrapper { scrollbar-gutter: stable; } }`.
- **Nested opacity slider overflow.** Carbon `.bx--slider` has a default `min-width: ~12.5rem` and won't shrink in a narrowed container. In `MapToolLayerControl.svelte`, wrap the Slider and override `:global(.bx--slider){min-width:0; flex:1 1 auto}` + `:global(.bx--slider-container){width:100%}` (the `min-width:0` override is the critical part).
